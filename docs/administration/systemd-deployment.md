# Systemd Deployment with External Mosquitto

This recipe runs homeCore as a native systemd service next to an external
Mosquitto broker that enforces per-topic ACLs, which the embedded rumqttd
does not. For the trade-off between the two, read
[the broker guide](./broker#external-mosquitto-deployment) first.

homeCore uses Mosquitto through `[broker] external_url`, which needs
v0.1.97 or later. Earlier versions ignored that key, always started the
embedded broker on `[broker].port`, and collided with a Mosquitto on the
same port.

With Docker instead, the core repository has a compose variant at
`core/docker/docker-compose.external-broker.yml`. It uses the same
generated files.

The steps assume Debian or Ubuntu with `systemd` and `apt`. On Red Hat,
Arch or NixOS, adjust the package names and paths.

If you don't need Mosquitto, `scripts/install-service.sh` installs the
plain unit; see the [deployment checklist](./deployment-checklist#systemd-linux).

## Layout

When you're done:

```
/etc/homecore/
├── homecore.toml                 # homeCore config

/etc/mosquitto/
├── mosquitto.conf                # generated by hc-cli
├── aclfile                       # generated ACL file
├── passwd                        # hashed by passwd.setup.sh
└── conf.d/                       # standard drop-in dir (unused here)

/var/lib/homecore/                # homeCore's home (HOMECORE_HOME)
├── INITIAL_ADMIN_PASSWORD        # first boot only; delete after login
├── data/                         # state.redb, history.db, audit.db,
│                                 # jwt_secret (0600)
├── rules/                        # automation rule files
├── config/plugins/               # settings of plugins installed from the Catalog
├── plugins/                      # plugins installed from the Catalog
├── backups/                      # scheduled backups
└── logs/                         # file log, unless [logging.file].dir is set

/var/log/homecore/                # file log, if [logging.file].dir points here

/etc/systemd/system/
├── homecore.service              # homeCore unit
└── mosquitto.service.d/override.conf  # optional: tighten Mosquitto
```

Relative paths in `homecore.toml` resolve against homeCore's home, which
the unit below sets to `/var/lib/homecore`.

## 1. Install Mosquitto

```bash
sudo apt install -y mosquitto mosquitto-clients
sudo systemctl stop mosquitto
```

Stop it straight away. You replace its configuration in step 4.

## 2. Install homeCore

From source:

```bash
cd homeCore/core
cargo build --release
sudo install -m 0755 target/release/homecore /usr/local/bin/
sudo install -m 0755 target/release/hc-cli /usr/local/bin/
```

From a release archive, extract it and copy the two binaries the same
way.

Create the service user and directories:

```bash
sudo useradd --system --home-dir /var/lib/homecore --shell /usr/sbin/nologin homecore
sudo install -d -o homecore -g homecore -m 0750 /var/lib/homecore
sudo install -d -o homecore -g homecore -m 0750 /var/log/homecore
sudo install -d -o root     -g homecore -m 0750 /etc/homecore
```

## 3. Write `homecore.toml`

Put the config at `/etc/homecore/homecore.toml`. For this setup the parts
that matter are `external_url` and `[[broker.clients]]`, with one entry
for homeCore and one for each plugin and runtime:

```toml
[broker]
# Use Mosquitto; the embedded broker doesn't start.
external_url = "mqtt://127.0.0.1:1883"
# homeCore logs in to Mosquitto as internal.core. hc-cli reads the
# [[broker.clients]] entries below to write Mosquitto's ACL and password files.

[[broker.clients]]
id       = "internal.core"
password = "<strong plaintext password for homeCore itself>"
allow_pub = ["homecore/#"]
allow_sub = ["homecore/#"]

[[broker.clients]]
id       = "plugin.thermostat"
password = "<the password in the plugin's own config>"
allow_pub = ["homecore/devices/+/state",
             "homecore/devices/+/state/partial",
             "homecore/devices/+/availability",
             "homecore/devices/+/cmd",
             "homecore/plugins/plugin.thermostat/#"]
allow_sub = ["homecore/devices/+/cmd",
             "homecore/devices/+/state",
             "homecore/devices/+/state/partial",
             "homecore/plugins/plugin.thermostat/#",
             "homecore/system/#"]

# ...one [[broker.clients]] block per plugin and runtime.
```

The thermostat plugin is a good example because it reads other devices'
state and commands them. Most plugins need only their own devices'
topics, so narrow `homecore/devices/+/…` to their device id prefix where
you can.

Each plugin's own config must point at Mosquitto too
(`broker_host = "127.0.0.1"`, `broker_port = 1883` in its `[homecore]`
table), with the same `password` as its entry here. Plugins installed from
the Catalog after `external_url` is set get that address when they are
installed, and a new random password in
`/var/lib/homecore/config/plugins/<plugin_id>.toml`. Copy that password
into a new `[[broker.clients]]` entry.

The passwords are plaintext, so lock the file down:

```bash
sudo chown root:homecore /etc/homecore/homecore.toml
sudo chmod 0640 /etc/homecore/homecore.toml
```

With the file read-only to the service, saving under **Settings ›
Configuration** in the web app fails, and so does anything else that
edits `homecore.toml` from the app. Make changes in the file and restart.
If you'd rather edit from the app, make the file writable by `homecore`
and add `/etc/homecore` to `ReadWritePaths=` in the unit.

## 4. Generate the Mosquitto config

```bash
sudo -u homecore hc-cli broker generate-mosquitto-config \
  --config /etc/homecore/homecore.toml \
  --out-dir /tmp/mosquitto-config
```

This writes three files to `/tmp/mosquitto-config/`:

- `mosquitto.conf`: a listener with anonymous access off, pointing at
  `/mosquitto/config/aclfile` and `/mosquitto/config/passwd`
- `aclfile`: topic rules for each user, from `allow_pub` and `allow_sub`
- `passwd.setup.sh`: a script of `mosquitto_passwd` commands

### Adjust paths for a native Mosquitto

The generated `mosquitto.conf` assumes Docker's `/mosquitto/config/...`
layout. A native install uses `/etc/mosquitto/...`:

```bash
sed -i 's#/mosquitto/config/#/etc/mosquitto/#g' /tmp/mosquitto-config/mosquitto.conf
sed -i 's#/mosquitto/data/#/var/lib/mosquitto/#g' /tmp/mosquitto-config/mosquitto.conf
```

`mosquitto.conf` then expects `/etc/mosquitto/aclfile` and
`/etc/mosquitto/passwd`.

### Fill in the real passwords

In `passwd.setup.sh`, replace each `CHANGE_ME_<ID>` with the plaintext
from the matching `[[broker.clients]].password`. Then run it. It empties
`passwd` and writes one hashed entry per client:

```bash
cd /tmp/mosquitto-config
bash passwd.setup.sh          # produces `passwd` next to the script
```

### Install the Mosquitto files

```bash
sudo install -m 0644 /tmp/mosquitto-config/mosquitto.conf /etc/mosquitto/
sudo install -m 0640 -g mosquitto /tmp/mosquitto-config/aclfile /etc/mosquitto/aclfile
sudo install -m 0600 -g mosquitto /tmp/mosquitto-config/passwd  /etc/mosquitto/passwd
rm -rf /tmp/mosquitto-config
```

`aclfile` and `passwd` must be readable by the `mosquitto` user and by
nobody else. `passwd` holds hashed credentials.

## 5. Install the homeCore unit

The template is `core/scripts/service-templates/homecore-mosquitto.service`.
The plain `homecore.service` next to it is for an install directory such
as `/opt/homecore`, and is what `scripts/install-service.sh` uses.

```ini
# /etc/systemd/system/homecore.service
[Unit]
Description=homeCore Home Automation Server (external Mosquitto)
After=network-online.target mosquitto.service
Wants=network-online.target
Requires=mosquitto.service

[Service]
Type=simple
User=homecore
Group=homecore
Environment="HOMECORE_HOME=/var/lib/homecore"
ExecStart=/usr/local/bin/homecore --config /etc/homecore/homecore.toml
# No ExecReload: homeCore has no SIGHUP handler, so a reload would stop it.
# Use `systemctl restart homecore` (or POST /system/restart) instead.

Restart=on-failure
RestartSec=5
StartLimitIntervalSec=60
StartLimitBurst=5

KillMode=control-group
KillSignal=SIGINT
TimeoutStopSec=30

StandardOutput=journal
StandardError=journal
SyslogIdentifier=homecore

# Hardening: safe defaults for a system service. Relax or tighten to
# match the rest of your host's posture.
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=read-only
ReadWritePaths=/var/lib/homecore /var/log/homecore
PrivateTmp=true
ProtectControlGroups=true
ProtectKernelModules=true
ProtectKernelTunables=true
RestrictRealtime=true
RestrictNamespaces=true
LockPersonality=true
MemoryDenyWriteExecute=true

[Install]
WantedBy=multi-user.target
```

Notes on the unit:

- `Requires=` and `After=mosquitto.service` mean homeCore waits for
  Mosquitto, and stops or restarts along with it.
- With `ProtectSystem=strict`, `ReadWritePaths=` lists the only places
  homeCore can write. Data, rules, plugins, backups and logs all default
  to `/var/lib/homecore`. If you move any of them, add the new path here.
- `HOMECORE_HOME` sets homeCore's home, which relative paths in
  `homecore.toml` resolve against. `--home <path>` does the same and takes
  precedence. Without either, homeCore uses its working directory.
- homeCore has no `SIGHUP` handler, so the unit has no `ExecReload` and
  `systemctl reload homecore` isn't supported. Use `systemctl restart
  homecore`. Units from templates older than v0.1.97 have an
  `ExecReload=/bin/kill -HUP $MAINPID` line, and `systemctl reload` on
  them stops homeCore for good. Delete that line and run
  `systemctl daemon-reload`.
- `KillMode=control-group` stops the plugins homeCore runs along with it.
- `POST /api/v1/system/restart`, and **Restart homeCore…** in the app,
  exit with code 75, which `Restart=on-failure` restarts. A stop by signal
  exits with code 0 and stays stopped. Before v0.1.97 the API restart also
  exited with 0, so homeCore stayed stopped under this unit.

## 6. Start everything

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now mosquitto
sudo systemctl enable --now homecore
```

On first start homeCore writes the admin password to
`/var/lib/homecore/INITIAL_ADMIN_PASSWORD`. Read it, sign in, change the
password, and delete the file.

## 7. Check it works

### Mosquitto is up and checking logins

```bash
journalctl -u mosquitto -f --since "2 min ago"
```

Expect a line like `mosquitto version 2.x starting`.

To see the ACL at work, try a publish it allows:

```bash
mosquitto_pub -h 127.0.0.1 -u plugin.thermostat \
  -P "<thermostat plaintext password>" \
  -t "homecore/devices/zwave_37/cmd" -m '{"on":true}' -d
```

`plugin.thermostat` has `homecore/devices/+/cmd` in its `allow_pub`, so
this goes through. Now try a topic outside its ACL:

```bash
mosquitto_pub -h 127.0.0.1 -u plugin.thermostat \
  -P "<password>" \
  -t "homecore/plugins/plugin.zigbee/register" -m '{}' -d
```

Mosquitto drops the publish and logs the denial. The embedded broker
would have accepted it.

### homeCore is up

```bash
journalctl -u homecore -f --since "2 min ago"
curl http://127.0.0.1:8080/api/v1/health
```

Expect `{"status":"ok","version":"..."}`.

### Plugins connect

Each plugin logs its broker connection at INFO. Or check from Mosquitto's
side:

```bash
journalctl -u mosquitto -g 'New client connected'
```

Each entry should show the plugin's id, such as `plugin.lutron`. If
Mosquitto reports a client as not authorized, the plugin is sending the
wrong password: check that its config file has the same plaintext you put
in `passwd.setup.sh`.

## Operations

### Rotating a plugin password

1. Make a new plaintext secret.
2. Put it in the plugin's own config file.
3. Put it in the matching `[[broker.clients]].password` in
   `/etc/homecore/homecore.toml`.
4. Regenerate and reinstall Mosquitto's password file:
   ```bash
   sudo -u homecore hc-cli broker generate-mosquitto-config \
     --config /etc/homecore/homecore.toml \
     --out-dir /tmp/mc --force
   # Edit passwd.setup.sh, replace the placeholders, run it, copy `passwd`.
   sudo install -m 0600 -g mosquitto /tmp/mc/passwd /etc/mosquitto/passwd
   ```
5. `sudo systemctl reload mosquitto` picks up the new `passwd` without
   dropping clients already logged in. The new password applies from
   their next connection. To make everyone log in again now, use
   `sudo systemctl restart mosquitto`.

### Changing a plugin's topics

Edit `allow_pub` and `allow_sub` in its `[[broker.clients]]` entry, then
regenerate and install only the ACL file:

```bash
sudo -u homecore hc-cli broker generate-mosquitto-config \
  --config /etc/homecore/homecore.toml \
  --out-dir /tmp/mc --force
sudo install -m 0640 -g mosquitto /tmp/mc/aclfile /etc/mosquitto/aclfile
sudo systemctl reload mosquitto
```

Mosquitto rereads the ACL on `SIGHUP`, which `systemctl reload` sends.

### Adding a plugin

1. Install it from the Catalog, or install its binary and config by hand.
2. Add a `[[broker.clients]]` block for it in `homecore.toml`, with the
   password from its config file.
3. Regenerate everything with `generate-mosquitto-config --force`.
4. Fill in every password in the new `passwd.setup.sh`, the new plugin's
   and all the old ones, and run it. The script rewrites `passwd` from
   scratch, so an entry left as a placeholder ends up with the placeholder
   as its password.
5. Install the new `aclfile` and `passwd`, then
   `systemctl reload mosquitto`.

A [plugin runtime](../plugins/runtimes) is the same: its login is its
plugin id and the key homeCore showed when you added it.

## Troubleshooting

**homeCore and Mosquitto both want port 1883.**
homeCore started its embedded broker, which happens when `external_url`
is unset or empty, or on a version before v0.1.97. Check that
`[broker] external_url` is set in the config the unit loads, and look for
`Using an external MQTT broker` in `journalctl -u homecore`. See what
holds the port with `ss -tlnp | grep 1883`.

**homeCore starts but never connects to Mosquitto.**
Mosquitto's log shows `internal.core` refused, or nothing from it. Check
that `[[broker.clients]]` has an `internal.core` entry and that its
password matches the one in Mosquitto's `passwd`. homeCore logs a warning
if the broker hasn't answered after 30 seconds, and starts plugins once it
does.

**Plugins connect, but Mosquitto's log fills with denied publishes.**
The plugin publishes outside its ACL. Either the ACL is too narrow (fix
`allow_pub`) or the plugin misbehaves. Compare with the topics in the
[broker guide](./broker#topics).

**A plugin logs in, but homeCore never sees its state.**
Its `allow_pub` doesn't cover its state topic. This often happens after
device ids change and the ACL patterns don't.

**Mosquitto's log is nearly empty.**
The generated config logs errors, warnings, notices and information only.
Add `log_type debug` to `mosquitto.conf` while you debug.

## Upgrading

1. Back up (`POST /api/v1/system/backup`, or **Back up now** in the app)
   and read the [release notes](../release-notes) for upgrade steps.
2. Install the new `homecore` and `hc-cli` binaries over the old ones.
3. `sudo systemctl restart homecore`.
4. Update plugins from **Settings › Plugins** (**Update all**). Plugins
   live in homeCore's home, so upgrading core leaves them as they were.
