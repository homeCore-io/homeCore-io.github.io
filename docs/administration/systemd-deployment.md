# Systemd Deployment with External Mosquitto

This is a recipe for running homeCore as a native systemd service next to
an external Mosquitto broker that **enforces per-topic ACLs**, which the
embedded rumqttd does not. If you're new to the trade-off between the
embedded broker and an external one, read
[the broker guide](./broker#external-mosquitto-deployment) first.

:::warning homeCore cannot yet use an external broker
In homeCore 0.1.96 there is no working `[broker] external_url` setting.
The server ignores that key, always starts its embedded broker, and
connects its own client to `127.0.0.1` on `[broker].port`. The Mosquitto
half of this guide (steps 1 and 4, and the operations section) works as
written, but homeCore will not route its traffic through Mosquitto until
that setting exists. If both brokers are configured for port 1883 on the
same host, they will collide. Until then, use the embedded broker with
`[[broker.clients]]` credentials, as described in
[the broker guide](./broker#password-authentication).
:::

If you prefer Docker, the compose variant is in the core repo at
`core/docker/docker-compose.external-broker.yml`. It uses the same
generated files with different packaging, and carries the same
limitation.

This guide assumes a Debian/Ubuntu-style distribution with `systemd` and
`apt`. On Red Hat, Arch or NixOS, adapt the package names and paths.

---

## Layout

By the end you'll have:

```
/etc/homecore/
├── homecore.toml                 # HomeCore config

/etc/mosquitto/
├── mosquitto.conf                # generated by hc-cli
├── aclfile                       # generated ACL file
├── passwd                        # hashed from passwd.setup.sh
└── conf.d/                       # standard drop-in dir (unused here)

/var/lib/homecore/                # homeCore's home (HOMECORE_HOME)
├── INITIAL_ADMIN_PASSWORD        # first boot only; delete after login
├── data/                         # state.redb, history.db, audit.db,
│                                 # jwt_secret (0600)
├── rules/                        # automation rule files
├── backups/                      # scheduled backups
└── logs/                         # file log, unless [logging.file].dir is set

/var/log/homecore/                # file log, if [logging.file].dir points here

/etc/systemd/system/
├── homecore.service              # HomeCore unit
└── mosquitto.service.d/override.conf  # optional: tighten Mosquitto
```

Relative paths in `homecore.toml` resolve against homeCore's home, which
the unit below sets to `/var/lib/homecore`.

## 1. Install Mosquitto

```bash
sudo apt install -y mosquitto mosquitto-clients
sudo systemctl stop mosquitto
```

Stop it straight away: you'll replace its default configuration in step 4.

## 2. Install homeCore

If you build from source:

```bash
cd homeCore/core
cargo build --release
sudo install -m 0755 target/release/homecore /usr/local/bin/
sudo install -m 0755 target/release/hc-cli /usr/local/bin/
```

If you use a prebuilt tarball, extract it under `/opt/homecore` and copy
the binaries the same way.

Create the service user and directories:

```bash
sudo useradd --system --home-dir /var/lib/homecore --shell /usr/sbin/nologin homecore
sudo install -d -o homecore -g homecore -m 0750 /var/lib/homecore
sudo install -d -o homecore -g homecore -m 0750 /var/log/homecore
sudo install -d -o root     -g homecore -m 0750 /etc/homecore
```

## 3. Write `homecore.toml`

Put your config at `/etc/homecore/homecore.toml`. The part that matters
for this deployment is `[[broker.clients]]`, one entry per MQTT client:

```toml
[broker]
external_url = "mqtt://127.0.0.1:1883"
# NOTE: homeCore 0.1.96 ignores external_url (see the warning above).
# hc-cli reads the [[broker.clients]] entries below to generate the
# Mosquitto ACL and password files.

[[broker.clients]]
id       = "internal.core"
password = "<strong plaintext password for homeCore itself>"
allow_pub = ["homecore/#"]
allow_sub = ["homecore/#"]

[[broker.clients]]
id       = "plugin.thermostat"
password = "<strong plaintext password>"
allow_pub = ["homecore/devices/thermostat_+/state",
             "homecore/plugins/plugin.thermostat/+",
             "homecore/devices/+/cmd"]
allow_sub = ["homecore/devices/thermostat_+/cmd",
             "homecore/devices/+/state",
             "homecore/devices/+/state/partial"]

# ...one [[broker.clients]] block per plugin.
```

The passwords are plaintext, so lock the file down:

```bash
sudo chown root:homecore /etc/homecore/homecore.toml
sudo chmod 0640 /etc/homecore/homecore.toml
```

## 4. Generate the Mosquitto config from `homecore.toml`

```bash
sudo -u homecore hc-cli broker generate-mosquitto-config \
  --config /etc/homecore/homecore.toml \
  --out-dir /tmp/mosquitto-config
```

This produces three files under `/tmp/mosquitto-config/`:

- `mosquitto.conf`: a listener with anonymous access off, pointing at
  `/mosquitto/config/aclfile` and `/mosquitto/config/passwd`
- `aclfile`: per-user topic rules derived from `allow_pub` / `allow_sub`
- `passwd.setup.sh`: a helper script of `mosquitto_passwd` commands

### Adjust paths for a native (non-Docker) Mosquitto

The generated `mosquitto.conf` assumes Docker's `/mosquitto/config/...`
layout. A native install uses `/etc/mosquitto/...`:

```bash
sed -i 's#/mosquitto/config/#/etc/mosquitto/#g' /tmp/mosquitto-config/mosquitto.conf
sed -i 's#/mosquitto/data/#/var/lib/mosquitto/#g' /tmp/mosquitto-config/mosquitto.conf
```

After this, `mosquitto.conf` expects `/etc/mosquitto/aclfile` and
`/etc/mosquitto/passwd`.

### Fill in the real passwords

Edit `passwd.setup.sh` and replace each `CHANGE_ME_<ID>` with the same
plaintext you put in the matching `[[broker.clients]].password` field.
Then run it. It empties `passwd` and writes one entry per client, hashed
by Mosquitto's `mosquitto_passwd`:

```bash
cd /tmp/mosquitto-config
bash passwd.setup.sh          # produces `passwd` next to the script
```

### Install the Mosquitto files

```bash
sudo install -m 0644 /tmp/mosquitto-config/mosquitto.conf /etc/mosquitto/
sudo install -m 0640 -g mosquitto /tmp/mosquitto-config/aclfile /etc/mosquitto/aclfile
sudo install -m 0600 -g mosquitto /tmp/mosquitto-config/passwd  /etc/mosquitto/passwd
rm -rf /tmp/mosquitto-config
```

`aclfile` and `passwd` must be readable by the `mosquitto` user and not
world-readable (`passwd` contains hashed credentials).

## 5. Install the homeCore systemd unit

The template for this setup is
`core/scripts/service-templates/homecore-mosquitto.service`. (The plain
`homecore.service` template next to it is for an install directory such
as `/opt/homecore`, and is what `scripts/install-service.sh` uses.)

```ini
# /etc/systemd/system/homecore.service
[Unit]
Description=HomeCore Home Automation Server
Documentation=https://github.com/homeCore-io/homeCore
After=network-online.target mosquitto.service
Wants=network-online.target
Requires=mosquitto.service

[Service]
Type=simple
User=homecore
Group=homecore
Environment="HOMECORE_HOME=/var/lib/homecore"
ExecStart=/usr/local/bin/homecore --config /etc/homecore/homecore.toml
ExecReload=/bin/kill -HUP $MAINPID

Restart=on-failure
RestartSec=5
StartLimitIntervalSec=60
StartLimitBurst=5

KillMode=control-group
KillSignal=SIGINT
TimeoutStopSec=30

StandardOutput=journal
StandardError=journal
SyslogIdentifier=homecore

# Hardening — safe defaults for a system service.
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=read-only
ReadWritePaths=/var/lib/homecore /var/log/homecore
PrivateTmp=true
ProtectControlGroups=true
ProtectKernelModules=true
ProtectKernelTunables=true
RestrictRealtime=true
RestrictNamespaces=true
LockPersonality=true
MemoryDenyWriteExecute=true

[Install]
WantedBy=multi-user.target
```

Notes on the unit:

- `Requires=mosquitto.service` with `After=mosquitto.service` means
  homeCore won't start until Mosquitto is up, and is stopped or restarted
  along with it.
- `ReadWritePaths=` lists the only writable directories once
  `ProtectSystem=strict` applies. The default locations for data, rules,
  backups and logs are all under `/var/lib/homecore`. If you point any of
  them elsewhere, add that path here.
- `HOMECORE_HOME` sets homeCore's home directory, which relative paths in
  `homecore.toml` resolve against. `--home <path>` on the command line
  does the same and takes precedence. Without either, homeCore uses its
  working directory.
- homeCore has no `SIGHUP` handler, so don't use `systemctl reload
  homecore`. Use `systemctl restart homecore`.
- `KillMode=control-group` stops the plugins homeCore supervises along
  with it.
- `POST /api/v1/system/restart` (and restarting from the web app) shuts
  homeCore down with exit code 0 and expects the supervisor to start it
  again. `Restart=on-failure` doesn't restart after a clean exit, so set
  `Restart=always` if you want that to work.

## 6. Start everything

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now mosquitto
sudo systemctl enable --now homecore
```

On first start homeCore writes the generated admin password to
`/var/lib/homecore/INITIAL_ADMIN_PASSWORD`. Read it, sign in, change the
password, and delete the file.

## 7. Verify

### Mosquitto is up and authenticating

```bash
journalctl -u mosquitto -f --since "2 min ago"
```

Expect a line like `mosquitto version 2.x starting`.

To show that the ACL is enforced, try a publish the ACL allows:

```bash
mosquitto_pub -h 127.0.0.1 -u plugin.thermostat \
  -P "<thermostat plaintext password>" \
  -t "homecore/devices/zwave_37/cmd" -m '{"on":true}' -d
```

`plugin.thermostat` has `homecore/devices/+/cmd` in its `allow_pub`, so
this succeeds. Now try a topic outside its ACL:

```bash
mosquitto_pub -h 127.0.0.1 -u plugin.thermostat \
  -P "<password>" \
  -t "homecore/plugins/plugin.zigbee/register" -m '{}' -d
```

Mosquitto drops the publish and logs that it was denied. The embedded
broker would have accepted it.

### homeCore is up

```bash
journalctl -u homecore -f --since "2 min ago"
curl http://127.0.0.1:8080/api/v1/health
```

Expect `{"status":"ok","version":"..."}`.

### Plugins connect

Each plugin logs its broker connection at INFO. Tail their logs, or check
from Mosquitto's side:

```bash
journalctl -u mosquitto -g 'New client connected'
```

Each entry should show the plugin's client id (e.g. `plugin.lutron`). If
Mosquitto reports a client as not authorised, the plugin is presenting the
wrong password: check that its config file carries the same plaintext you
put in `passwd.setup.sh`.

## Operations

### Rotating a plugin password

1. Generate a new plaintext secret.
2. Update the plugin's own config file with it.
3. Update the matching `[[broker.clients]].password` in
   `/etc/homecore/homecore.toml`.
4. Regenerate and reinstall the Mosquitto password file:
   ```bash
   sudo -u homecore hc-cli broker generate-mosquitto-config \
     --config /etc/homecore/homecore.toml \
     --out-dir /tmp/mc --force
   # Edit passwd.setup.sh, replace placeholders, run it, copy `passwd`.
   sudo install -m 0600 -g mosquitto /tmp/mc/passwd /etc/mosquitto/passwd
   ```
5. `sudo systemctl reload mosquitto` picks up the new `passwd` without
   disconnecting clients that are already authenticated. The new password
   applies from the next CONNECT. To force everyone to re-authenticate
   now, use `sudo systemctl restart mosquitto` instead.

### Changing a plugin's allowed topics

Edit the `allow_pub` / `allow_sub` arrays in `[[broker.clients]]`, then
regenerate and install only the ACL file:

```bash
sudo -u homecore hc-cli broker generate-mosquitto-config \
  --config /etc/homecore/homecore.toml \
  --out-dir /tmp/mc --force
sudo install -m 0640 -g mosquitto /tmp/mc/aclfile /etc/mosquitto/aclfile
sudo systemctl reload mosquitto
```

Mosquitto re-reads the ACL on `SIGHUP`, which is what `systemctl reload`
sends.

### Adding a new plugin

1. Add a `[[broker.clients]]` block for it in `homecore.toml`.
2. Regenerate everything with `generate-mosquitto-config --force`.
3. Fill in every password in the new `passwd.setup.sh` (the new plugin's
   and all the existing ones) and run it. The script rewrites `passwd`
   from scratch, so any entry you leave as a placeholder ends up with that
   placeholder as its password.
4. Install the updated `aclfile` and `passwd`, then
   `systemctl reload mosquitto`.
5. Install the plugin binary and its own config, using the same plaintext
   password.

## Troubleshooting

**homeCore and Mosquitto both want port 1883.**
Because homeCore always starts its embedded broker (see the warning at the
top), it and Mosquitto can't both listen on 1883. Check what holds the
port with `ss -tlnp | grep 1883`.

**Plugins connect, but Mosquitto's log fills with denied publishes.**
The plugin is publishing outside its ACL. Either the ACL is too narrow
(fix `[[broker.clients]].allow_pub`) or the plugin is misbehaving. Compare
against the plugin's documented topics.

**A plugin authenticates, but homeCore never sees its state.**
The plugin's `allow_pub` doesn't cover its state topic. This often
happens after renaming a device ID when the ACL patterns weren't updated.

**Mosquitto's log is nearly empty.**
The generated config logs errors, warnings, notices and information only.
Add `log_type debug` to `mosquitto.conf` temporarily while debugging.
